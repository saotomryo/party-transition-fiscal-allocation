# 記事用：利用データ・集計方法・結果

記録日：2026-10-13。公開データから党派交代と財政配分の全体傾向を確認する。個別事情の追加検証は今回の対象外とする。

## 結果の表現

2021年衆院選前後の国庫支出金は4分類とも一人当たり配分が減少したが、野党から与党へ変わった地域では減少幅が小さかった。これは「与党への交代と配分上の有利な変化が関連する」という仮説と整合する記述的傾向で、公開データから再現できる。統計的な仮説支持、優遇の実証、政治的介入の証明とは区別する。条件調整後の同じ比較は判断保留である。

## 利用データと出典

- e-Stat 地方財政状況調査：2015〜2024決算年度の国庫支出金、普通交付税、特別交付税、震災復興特別交付税、財政力指数。https://www.e-stat.go.jp/stat-search/files?layout=dataset&toukei=00200251
- e-Stat 住民基本台帳に基づく人口、人口動態及び世帯数調査：決算年度翌年1月1日の日本人＋外国人総計人口。https://www.e-stat.go.jp/stat-search/files?layout=dataset&toukei=00200241
- 総務省の2014・2017・2021・2024衆院選の正式当落表と市区町村別得票表。前後の全国集計は2017・2021年。
- 政権参加の公式確認資料：対象期間は自民党・公明党を与党と判定。出典URLはanalysis-report.jsonとsource-report.json。

個々の取得URL・確認時刻・原本SHA256はfinance-sources.json、election-sources.json、certification-report.jsonに保存。原本不整合や未対応地域も記録してある。原本自体はdata/rawとdata/elections/rawに保存し、この記事用フォルダには同梱していない。

## 4分類の集計方法

1. 自治体コードはチェック桁を含む6桁文字列。市町村・特別区を対象とし、政令市行政区は親市へ対応。財政額の原本単位「千円」を円へ変換。
2. 前回・今回の小選挙区当選時党派から4分類を作る。議員個人の連続党籍履歴とは異なり、期中の党籍変更・補選・比例復活は未反映。
3. 複数小選挙区、無所属などの未判別、名称未確認、前後で選挙区番号または所属自治体集合が変わる地域は除外。変化率の高い自治体だけを選ばない。構成一致は地理的境界の完全一致を証明しない。
4. 選挙年度は除外し、前後各1年度または各2年度を比較。2021年の2年度窓は2019/2020年度と2022/2023年度、1年度窓は2020年度と2022年度。2017年の2年度窓は2015/2016年度と2018/2019年度。
5. 年度別の額を対応する人口で割り、自治体ごとに前期間と後期間の平均を求める。両期間の全年度が揃う自治体のみ採用し、欠測をゼロ補完しない。
6. 分類ごとに自治体の期間平均を等重みで平均する。全国住民の人口加重平均ではない。増減額＝後平均−前平均。参考変化率＝増減額÷前平均×100。前平均ゼロなら率は欠測。自治体別変化率の平均ではない。
7. 控除後国庫支出金は、確認できたコロナ交付金の親項目2つと災害復旧事業費支出金を控除。子項目の二重控除をしない。全関連支出を除いた額ではない。

## 条件調整結果との区別

adjusted-results.csvには全32比較を保存。回帰では選挙前年人口・財政力指数・都道府県・団体区分を調整し、同じ都道府県×団体区分に交代群と継続群がある範囲を使うため、4分類表とは対象数が異なる。標準誤差は小選挙区単位。24比較を推定、8比較は保留。詳細な不確実性・多重比較・事前傾向の扱いはanalysis-report.jsonとREADMEを参照。記述的傾向を調整後に有意な結果として紹介しない。

## 再現・版管理

READMEに従ってfinance.py → elections.py → certify_results.py → alignment.pyを実行。4分類集計はanalysis_view.pyのfour_group_amountsを使用。snapshot.jsonに今回の入力・コードのSHA256を記録。収集はhost側、閲覧は生成済みデータを使用。アプリ画面からの表CSV・結果ZIP保存も可能。
